The problem

Four lanes, one Monday

A new Professor of Defence Against the Dark Arts starts on Mon 16 Nov. Recruiting, provisioning, the buddy and the welcome all have to be ready. Each lane looks fine on its own. The failures sit between them.

  • Recruiter × Provisioning

    The ledger sets the clock

    The Personnel Ledger says 23 November. Provisioning triggers off the ledger, so the Portkey would be filed after the Professor should already be in the castle.

  • Provisioning × Welcome

    One Thursday, two deadlines

    Thu 5 Nov is the last day to file the Portkey and the last day to order the nut-free hamper. Different lanes, same morning.

  • Recruiter × Buddy × Welcome

    Some facts must not travel

    The Recruiter knows the Professor is an unregistered Animagus. The buddy briefing and the welcome letter must never say so.

Design decisions

Six choices that make it behave

  • Each specialist owns its library

    The Lead briefs and does not relay policy, so nothing is paraphrased on the way. Re-running the setup script refreshes the libraries.

  • Dates are computed, never recalled

    Every agent has to run bash for business-day arithmetic. The Portkey clock is exactly the kind of thing a model gets wrong in its head.

  • The Lead can call four agents

    Inline agents and workflows are switched off. The roster is the team, and spend cannot fan out.

  • Restricted details have a rule

    The accommodation is only ever "quarters and classroom setup". Every scroll is tagged Staff Affairs only or Shareable.

  • A spend ceiling and a safe re-run

    The session stops at $15 of list cost. The setup script updates agents in place instead of piling up copies.

  • HTML instead of a Word file

    The agents write the page straight into the session's outputs folder. No document skill is needed, and the theme is just CSS.
